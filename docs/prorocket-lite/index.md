# ProRocket Lite

The code generator. Give it your XSD or WSDL files, and it writes the Delphi units for them.

## Two ways to run it

The zip holds one generator with two faces, and both give the same units.

- **[GUI](../gui.md)**, `ProRocket.Lite.exe`: add the files, click **Generate**, see the code
- **[Command line](../cli.md)**, `ProRocketCli.exe`: for scripts, build steps and AI coding assistants

## What goes in

The main XSD or WSDL and every file it imports and includes, all in one run. A missing one is reported by name, so you can add it
and run again.

The standard schemas are part of ProRock, and you do not give them: XML Schema itself, `xml:` and `xsi:` attributes, the SOAP
envelopes, WSDL and its SOAP bindings.

## What comes out

- **one unit per XML namespace**: `ProRock.Xmlite.Schema.<Name>.pas`, the types and elements of that namespace
- **one client unit per `wsdl:service`**: `ProRock.Soapite.<Service>.pas`, see [SOAP](../soapite.md)
- **deterministic output**: an unchanged schema gives an unchanged unit, so a schema update shows up as a clean diff

What a schema construct becomes in Delphi: [Generated code](../generated-code.md).

The unit header names the ProRock release the unit is made for ("Generated by ProRocket Lite for ProRock 1.7.0"); use that
release of the library.

## Its own first user

ProRocket Lite reads XSD and WSDL through ProRock, with classes it generated itself. The units for XML Schema, WSDL and SOAP in
ProRock (`ProRock.Xmlite.Schema.Base`, `.Wsdl`, `.Soap`, ...) are generated from their official schemas and regenerated with
every release, so the generator is tested on each of them all the time.

You do not need the generator to use the library: for a small format without a schema,
[write the classes by hand](../hand-written.md).
